# AI 立体几何交互可视化系统 — PRD + 技术设计（v1.0）

> 面向：高中数学学习助手 / Codex 开发代理  
> 状态：可执行的产品与工程设计草案；最终技术选型必须以现有代码仓库为准。  
> 产品目标：学生拍照上传几何题，AI 解析题意并生成**符合题设约束**的可交互 2D/3D 数学场景；学生通过拖动、折叠、构造、选点连线和自定义测量观察几何量变化，从而理解题目，而不是只观看一段 3D 动画。

---

## 0. 一句话定义与关键决策

这是 **AI + 动态几何引擎 + 交互式教学界面**，不是单纯的图片转 3D 模型。

基本职责分离：

- **AI**：从图像/文字提取数学事实、消除歧义、提出几何建模方案、为问题选择适当的可视化等级、建议可交互自由度与观察量、生成解释文本。
- **几何引擎**：将数学事实编译为点、线、面、刚体、约束、参数和可计算指标；校验可解性；维护运动中的约束；独立计算所有数值。
- **3D 引擎**：渲染几何场景、标签和测量辅助图元；提供选中/拖动/镜头/动画等交互。
- **用户**：查看题面、确认 AI 的理解、编辑参数、探索允许的几何变化、添加辅助构造与观察量。

**不可妥协的原则：**
1. 题图只是示意，**不能按像素比例推断题目未明确给出的长度/角度**。
2. AI 输出的是**受控的声明式 GeometryScene JSON**，不得让模型任意生成并执行 JS/Python 代码。
3. 几何关系由程序验证；LLM 自报“有信心”不足以证明几何正确。
4. 学生拖动时默认保持原题全部**硬约束**；需要破坏约束时，必须进入单独的“自由探索”模式并明显提示。
5. 所有量测值由几何引擎实时计算，不能由 LLM 在每帧中猜测。
6. **解读不确定时先展示候选构型、待确认条件或低等级场景**，不能编造唯一正确空间模型。

## 1. 用户、使用场景、成功标准

### 1.1 目标用户
- 主要：高一至高三学生，尤其是空间想象能力薄弱的学生。
- 次要：老师，用于演示折叠、线面位置关系、空间角与体积最值。

### 1.2 核心任务（Jobs to be Done）
1. “我拍了一道折叠题，希望看到纸面到底怎样折到空间中。”
2. “我看不懂哪两条线/哪个二面角，希望点一下就能高亮并转到合适视角。”
3. “题目中存在可变参数，我想拖动它，看到长度/距离/角度怎样改变。”
4. “我想自己选两个点连辅助线，或选点与平面显示垂线、距离。”
5. “我想知道哪些位置满足题设，以及某个最值为何出现在那里。”
6. “如果 AI 对图片理解错了，我可以低成本修正，而不是重新拍题。”

### 1.3 产品成功指标（建议；上线前用数据集重新定标）
- 覆盖代表性题型：静态长方体/棱锥、平面图形翻折、线面角、面面角、点线面距离及单参数最值。
- 对**声明支持**的黄金测试题，所有硬约束始终满足数值容差；不允许“画面看起来对、数学却错”。
- 95% 以上的合法基础交互无程序异常；不支持的复杂题明确降级。
- 关键交互：选点→连线、自选测量、折叠滑块、重置、撤销均可完整跑通。
- 桌面目标交互帧率 ≥30 FPS（合理规模场景），拖动→数据更新的典型延迟 <100 ms；具体以设备基准实测调整。
- 记录：解析成功率、几何验证成功率、回退级别、用户纠错率、首次有效交互时间。

## 2. 界面结构与交互设计

### 2.1 桌面主界面（三栏 + 底部时间/数值区）

```text
┌──────────────────────────────────────────────────────────────────────────────┐
│ 返回题目  | AI 几何实验室 | 重建状态：已验证 / 有待确认 | 视图切换 | 保存 │
├────────────────┬─────────────────────────────────┬───────────────────────────┤
│ ① 题目面板     │ ② 中央 3D 场景                   │ ③ 几何探索面板            │
│ 上传原题缩略图 │  轨道旋转 / 平移 / 缩放 / 正交视角│ [教学模式 | 构造模式]       │
│ 识别后的题目   │  几何点、线、面、虚线、标签       │ 对象：点/线/面/立体         │
│ 已知条件标签   │  选中点 A -> 显示约束与操作柄    │ 参数：折叠角 θ 滑块         │
│ 求证/求解目标  │  选中线 -> 高亮相关关系          │ 测量：AB / 高度 / 二面角     │
│ 可修正 AI 识别 │  [前视][俯视][等轴测][适配视野] │ 操作：连接点 / 做垂线       │
│                │  [添加线段][选择][重置镜头]      │ 信息：当前满足的题设关系     │
├────────────────┴─────────────────────────────────┴───────────────────────────┤
│ ④ 底部：展开进度 θ [━━━━━━━━━━●━━━━] 播放/暂停  | h(θ)=... | AB(θ)=...     │
│         [画出 h-θ 曲线] [标记最值] [回到初始] [恢复题目]                     │
└──────────────────────────────────────────────────────────────────────────────┘
```

主要设计：
- **场景是视觉核心**，最少占可用桌面宽度的约 50%，避免复杂右侧控件挤压主视图。
- 默认进入 **“学习模式”**：AI 只展示最重要的参数、关系、测量；大量高级控件折叠。
- 一键切换 **“自由构造模式”**：能自主创建点/线/面、选测量、显示坐标、隐藏面等。
- 右侧使用多级折叠面板而非一次性堆叠数十个工具。
- 每个条件支持“题面原文↔场景对象”的双向定位：点中条件“DE⊥BC”时，场景高亮 DE 和 BC。
- 对题目指定的求证/求值目标，以醒目但不干扰的方式标出关联点线面。

### 2.2 移动端/小屏
- 顶部题面可折叠，中心占主要区域，底部抽屉在“探索 / 测量 / 构造 / AI 提示”之间切换。
- 单指拖动选中对象，单指空白旋转场景，两指缩放/平移；关键参数始终提供滑块与数值输入作为非拖动替代。
- 不要求用户在手机上操作难以命中的 3D 微小点；点选使用扩大命中区域。

### 2.3 交互优先级与操作规则
| 操作 | 默认行为 | 限制/提示 |
|---|---|---|
| 点击点/线/面 | 选中、高亮、右侧显示属性 | 可锁定选中状态 |
| 空白拖动 | 旋转镜头 | 拖动对象期间禁用轨道控制 |
| 拖动可编辑点 | 沿允许约束流形移动，其他依赖对象更新 | 非法区域拒绝/投影回可行域 |
| 拖动固定点 | 不移动，显示“由题设固定” | 可查看固定原因 |
| 操作折叠 | 优先拖动角度滑块或折叠专用弧形手柄 | 刚体面不得变形，折痕端点不动 |
| 选择两点→连接 | 建立学生辅助线段，端点随场景更新 | 不改变题设约束 |
| 添加点 | 支持“线段上点”“平面上点”“自由点” | 优先结构化定位而非任意世界坐标 |
| 选择测量 | 选择对象后出现长度、角度、距离等可用项 | 类型不适用时解释原因 |
| 回到初始 | 重置参数与动态位置 | 保留辅助构造可配置 |
| 撤销/重做 | 撤销学生创建/修改的构造与参数操作 | 不撤销原始题设 |

### 2.4 题目验证与不确定性呈现
在题目面板显式显示：
- “AI 读取的已知条件”（附原图对应区域）；
- “由题设确定的几何关系”；
- “用于绘制的示意假设”（例如选了边长归一化为 1、某自由角取 60°）；
- “当前构型：满足题设 / 未通过校验 / 自由探索”；
- 对存在多种非全等构型的题目，提示“当前仅展示一种符合条件的构型，不能当作唯一解”。

## 3. 自动决定可视化程度：AI Visualization Planner

不要求每道题都做完整三维交互；采用**五级降级体系**。

| 等级 | 名称 | 显示形式 | 适用 |
|---|---|---|---|
| L0 | 不建模 | 原题 + 文字/数学公式 + 识别纠正 | 信息不足、图像不清、3D 无教学价值 |
| L1 | 静态几何 | 可自由转镜头的点线面模型，关键关系高亮 | 空间位置判断、线面垂直等 |
| L2 | 步骤动画 | 按步骤显示辅助线、投影、折叠、剖面 | 涉及构造步骤但缺少可调参数 |
| L3 | 参数驱动 | 可调自由度滑块 + 约束运动 + 实时测量 | 折叠角、滑动点、最值问题（MVP 核心） |
| L4 | 几何实验室 | L3 + 用户增加对象、自由定义测量、探索模式 | 学生希望自主构造与比较 |

**决策流程：**
1. 多模态解析器提取：题型、对象、条件、目标、未知量、示意图信息。
2. 分析是否存在真正的 3D 几何需求；纯二维问题可以交给 2D 画板，而不是强制 3D。
3. 构建约束图，判断是否有已知可操作自由度（DOF）。
4. 判断是否有清晰的“操作→量测变化”关系；若有，优先生成 L3。
5. 估算生成风险：图像歧义、约束不足/冲突、几何退化、计算复杂性。
6. 返回**不超过工程验证能力**的等级；验证失败自动降到 L2/L1/L0。
7. 用户可以主动请求“进入实验室”，但只有满足数学引擎能力的操作才能启用。

Planner 输出需包含：`recommended_level`、`reason`、`task_type`、`driving_parameters`、`highlight_entities`、`suggested_metrics`、`verification_status`、`fallback_level`。不允许只给一个 0~100 的“主观分数”来决定等级。

## 4. 功能需求清单（优先级）

### P0：必须实现的 MVP
- F-001 复用现有拍题上传流程，不重做照片上传/用户系统。
- F-002 从图片提取题目文字、符号、点名、已知条件、求证/求值目标；给出可编辑的结构化确认页。
- F-003 将题意转换为版本化 `GeometryScene` 数据，包含点/线/面/刚体、关系约束、自由参数和测量。
- F-004 几何模型验证：类型、引用、几何退化、硬约束残差、参数范围；不合法场景拒绝进入“已验证”。
- F-005 基础 3D 场景：旋转/缩放/平移、重置镜头、点线面标签、遮挡与虚线、透明度调整、选中高亮。
- F-006 折叠专用参数：给定折痕轴与活动面，刚体绕轴旋转，其他面固定，支持滑块、播放、暂停、复位。
- F-007 动态量测：点点距离、点面距离、线线夹角、线面角、面面角（清晰定义取角分支）、三棱锥体积（第一版可先完成前三种）。
- F-008 选点连辅助线：通过场景点击点 A、B 自动产生跟随位置更新的线段 AB。
- F-009 对参数运动进行约束校验：约束不满足时明确提示/停止更新，不静默输出错误数字。
- F-010 AI 可视化等级选择 + 不确定降级：至少 L0/L1/L3；L2 可在 P1 补强。
- F-011 题目级重置：恢复初始几何参数和相机，提供撤销/重做基本操作。
- F-012 至少内置 3 个不依赖 AI 的可交互样例，用来验证数学引擎与 UI。

### P1：第二阶段
- F-101 在边上加点（比例参数 t∈[0,1]）、面上加点（重心坐标）、添加垂足/中点/交点。
- F-102 选两线测角、选线与面测线面角、选两面及棱测二面角。
- F-103 用户自行创建动态监测指标，曲线图显示参数变化历史，标注局部/全局候选极值。
- F-104 学习引导：一步一步显示关键辅助线、垂线、法向量、投影及提示。
- F-105 双视图：原始平面布局（或折前构型）与折后 3D 并排/切换，同步高亮对象。
- F-106 手动修正 AI 几何关系并重新校验/编译；把可视化结果缓存到题目记录。
- F-107 按题型预设“折叠探索”“求角度”“求距离”“找最值”模式。

### P2：后续扩展
- F-201 通用多约束拖点求解器，支持交线、球面约束、圆周轨迹与多个独立自由度。
- F-202 自由添加平面、交线、截面、多面体，以及作图命令。
- F-203 数学关系自动发现、参数扫描/极值证明辅助、生成讲解与练习变式。
- F-204 保存/分享探索场景、教师自定义演示、录制交互回放。
- F-205 多候选几何场景对比、复杂题的辅助条件搜索。

### 明确不做（第一期）
- 不承诺任意一道高中几何题都能自动唯一重建。
- 不承诺通用可拖动 3D CAD 建模编辑器。
- 不允许 AI 任意执行其生成的场景脚本。
- 不自动把可视化中的近似极值当作数学证明。
- 不要求复杂的跨面碰撞模拟、物理布料折叠或实时多用户协作。

## 5. 数学核心：几何场景 IR / 约束图

### 5.1 关键对象（需要稳定 ID）
- `Point`：点，含 `id`、显示符号、位置表达式、状态（固定/依赖/自由/参数驱动）。
- `Segment`/`Line`/`Ray`：线段、直线、射线，注意数学含义不同。
- `Plane`：抽象无限平面，由 3 个非共线点或法向量定义；与可绘制的面片 `Face` 区分。
- `Face`：有顶点序的多边形面片，可属于固定或可动刚体。
- `RigidPanel`：刚体面组，折叠时整体运动。
- `Parameter`：自由标量，例如折叠角 θ、边上点比例 t、高度 h。
- `Constraint`：距离相等、平行、垂直、共线、共面、点在线段上、点在平面上、定角、铰链关系等。
- `Motion`：由参数驱动的构造（绕轴旋转、沿线滑动、边上插值）。
- `Metric`：需要观测的数学量，定义来自对象引用和数学计算函数。
- `Annotation`：原题中哪个区域对应哪个对象/条件，追溯解析来源。
- `Construction`：学生后加辅助对象，应有独立层，不覆盖题目对象。

### 5.2 约束不是视觉上的“连线”
- `AB = 4` 是长度约束。
- `AB ⟂ CD` 是方向约束，不要求两线相交。
- `A ∈ 平面 BCD` 是共面约束。
- `E = midpoint(A,B)` 是**构造依赖**，其位置必须在 A/B 变动时重新计算。
- “三角形 ADE 沿 DE 翻折”是**刚体绕轴旋转**，要保持 `AD`、`AE`、`DE` 的长度恒定。

### 5.3 拖动与自由度
**先找到独立参数，再允许拖动**。相较于“任意拖动点 + 实时求所有约束”，优先采用稳定的参数化运动：

1. 已知参数：折叠角 θ → 滑块，直接构造所有点坐标。
2. 点在线段 AB 上：`P=(1-t)A+tB`，`0≤t≤1`；拖动时将鼠标射线投影到 AB 求 t。
3. 点在固定平面：使用局部平面坐标 `(u,v)`，约束在可用区域。
4. 点在圆/球面：通过一个或两个角参数移动，保持半径不变。
5. 一般复杂约束：P2 才使用数值约束投影/最小二乘法，并必须保证连续性和可行域检查。

对于 3D 自由点，屏幕二维鼠标不能唯一确定三维位置：必须提供“选定拖动平面、选轴 gizmo、数字坐标输入”之一，绝不可从屏幕二维拖动凭空猜测深度。

### 5.4 数据真值与探索分层
- `problem_constraints`：题目硬约束，默认不可被学生修改。
- `model_assumptions`：为画出示意构型引入的自由参数/归一化长度；明确展示。
- `user_constructions`：辅助线、垂足、测量等，不改变题设。
- `sandbox_overrides`：自由探索时可能违反原题的状态，必须标明为“非题设构型”，不可混入题目求解结论。

### 5.5 数值健壮性
- 统一内部单位，角度使用弧度、UI 显示角度；区分“长度 4”和“单位未给定的比例”。
- 0 长度向量、三点共线不能定义平面、重合点线等要返回 `undefined + reason`，不能显示 NaN/Infinity。
- 线线夹角可默认采用 `[0°,90°]` 最小夹角；二面角需要指定“所取半平面/支撑棱”，不可只对平面法向量取绝对值后声称就是题目二面角。
- 展示数字时保留 2~4 位小数，但计算用双精度；数值近似不可宣称精确符号答案。
- 检查归一化硬约束残差、参数边界、面退化、自交（必要时）与运动连续性。
- 跟踪几何引擎的状态变更；任何依赖对象、标签、量测、曲线必须同一次事务刷新。

## 6. 从图片到可交互场景：处理流水线

```text
现有拍照 / 图片上传
          │
          ▼
① OCR + 视觉数学解析（文本、图中 A/B/C、已知条件、目标）
          │
          ▼
② Problem IR（数学事实、证据来源、歧义/缺失条件）
          │
          ▼
③ AI Visualization Planner（题型、推荐 L0-L4、交互自由度、指标）
          │
          ▼
④ Geometry Compiler（实例化已知构型 + 对象/运动/约束/测量）
          │
          ▼
⑤ Deterministic Validator（对象引用、量纲、残差、退化、动态采样）
          │               │
     验证通过         验证失败 / 低置信
          │               └─► 条件确认 / 降级 / 局部重建
          ▼
⑥ Interactive Viewer（3D 渲染 + 参数交互 + 数值更新）
          │
          ▼
⑦ 学生实验（添加辅助构造、指标、折叠对比、AI 提示）
```

**强建议拆开“理解问题”和“创建场景”的模型输出**。这样可以查看 AI 哪一步出错，并重试局部步骤。解析的每条条件应记录来自题面文字、图注还是仅来自图形猜测。

### 6.1 识别规则
- 从文字提取的硬条件优先于示意图位置；图形比例不能作为隐含数学条件。
- 对“点 D 为 AB 中点”“沿 EF 折叠”“A′ 是 A 翻折后的对应点”等条件转为结构化语义。
- 对视觉信息缺失（例如图内字母遮挡）显示“待确认”的具体字段。
- 文本可唯一约束的内容无需 AI 再“估个坐标”；坐标由编译器按规范选取。

### 6.2 构型唯一性
- 充分约束：生成满足条件的构型，保留坐标规范自由度（整体平移旋转不影响题目）。
- 欠约束：给出一组合法示意实例，暴露未确定的自由参数，明确说明不唯一。
- 矛盾条件：标红冲突，不生成看似正确的假场景。
- 立体几何存在镜像/多分支：列出分支或明确选择分支，并确认指标是否因分支变化。

### 6.3 AI 错误回退机制
- JSON 格式/对象引用错 → 使用 JSON Schema/类型验证给出字段级错误，有限次自动修复。
- 约束不满足 → 尝试编译器修复自由参数；若失败则展示待确认条件，降到静态/题面视图。
- 动态参数某段不可行 → 限定可用区间；无法校验时禁止该动态交互。
- 任何自动修复不应凭空增加题目条件。

## 7. 建议的 JSON 协议（示例）

这是工程可用的**概念格式**，开发时应定义严格的 TypeScript 类型和 JSON Schema/Zod 校验。所有表达式采用类型化 AST/白名单操作，不执行任意代码。

### 7.1 示例问题
“正方形 ABCD，边长 4；E 为 AB 中点。沿 DE 把三角形 ADE 翻折到空间，翻折角 θ 在 0° 到 90° 变化，观察 A 到平面 BCD 的距离以及 AB 的长度变化。”

### 7.2 GeometryScene（示意实例）

```json
{
  "schema_version": "1.0",
  "problem_id": "demo-square-fold",
  "geometry_status": "pending_validation",
  "source_facts": [
    {"id": "f1", "text": "ABCD 是边长为 4 的正方形", "provenance": "problem_text"},
    {"id": "f2", "text": "E 为 AB 中点", "provenance": "problem_text"},
    {"id": "f3", "text": "三角形 ADE 沿 DE 翻折", "provenance": "problem_text"}
  ],
  "entities": {
    "points": [
      {"id": "A", "label": "A′", "initial": [0, 0, 0], "role": "driven"},
      {"id": "B", "label": "B", "initial": [4, 0, 0], "role": "fixed"},
      {"id": "C", "label": "C", "initial": [4, 4, 0], "role": "fixed"},
      {"id": "D", "label": "D", "initial": [0, 4, 0], "role": "fixed"},

      {"id": "panel_ADE", "vertices": ["A", "D", "E"], "rigid": true},
      {"id": "base_EBCD", "vertices": ["E", "B", "C", "D"], "rigid": true}
    ]
  },
  "constraints": [
    {"id": "c1", "type": "fixed_length", "points": ["D", "E"], "value": 4.47213595499958},
    {"id": "c2", "type": "midpoint_at_initial", "point": "E", "of": ["A", "B"]},

    {"id": "theta", "label": "翻折角", "type": "angle", "unit": "rad", "min": 0, "max": 1.5707963267948966, "initial": 0.6, "step": 0.01}

```

> 注意：`midpoint_at_initial` 只在折前成立；翻折后不能错误地继续要求 E 是运动点 A′ 与 B 的中点。实际实现应将“折前点 A0”与“折后点 A′”分别表示成初始参考位置与当前活动位置，必要时提供带时间态/构型态的实体引用（例如 `initial(A)`、`current(A)`）。上述 JSON 是设计展示，不应原样作为无校验生产协议。

### 7.3 不可信输入边界
- AI 只能输出预定义实体、约束及操作类型，不接受任意 `eval`、代码字符串、动态模块导入。
- AI 输出 JSON 经过 schema、引用完整性、数学验证及计算复杂度预算限制。
- 题目图片中可能含“忽略指令”等提示注入文字，必须作为普通 OCR 数据处理，而不是系统指令。
- 文件大小、分辨率、面数、点数、求解迭代次数、递归依赖深度都必须有限制。

## 8. 动态计算与 3D 渲染架构

```text
Frontend / Web App
├─ ProblemPanel（图片、OCR 文本、题设修改）
├─ GeometryWorkbench（3D 主画布）
│  ├─ SceneRenderer（点、线、面、标签、隐藏线）
│  ├─ CameraController（Orbit/Orthographic/视角预设）
│  ├─ SelectionController（raycast / 选择集）
│  ├─ DragConstraintAdapter（屏幕拖动 -> 合法参数）
│  ├─ ConstructionTools（点、线、垂足、中点等）
│  └─ HighlightOverlay（垂直、夹角、长度、提示）
├─ GeometryStore（统一状态 + undo/redo）
├─ ParametricEvaluator（参数 -> 构型 -> 指标，客户端快速更新）
├─ InspectorPanel（对象树、参数、测量、条件）
└─ MetricPlot（数值、参数曲线、候选最值）

Backend / existing services
├─ ProblemImageService（复用）
├─ MultimodalProblemParser（AI 解析）
├─ VisualizationPlanner（分级+展示建议）
├─ SceneCompiler（Problem IR -> GeometryScene）
├─ GeometryValidator（数值、约束、运动抽样验证）
└─ SceneCache / ProblemPersistence（生成结果缓存）
```

### 8.1 建议技术选型
根据现有项目适配，不应为了加功能重写主应用。

**方案 A（建议用于与现有 Web 产品深度整合）：**
- 前端：`Three.js + React Three Fiber + @react-three/drei`（如果现有前端是 React）。
- 数学状态：轻量 store（如 Zustand）+ 独立 GeometryEvaluator；点线面的状态计算不绑定 React 组件树。
- JSON Schema 校验：Zod / Ajv 按现有项目规范选择。
- AI / 数值后端：沿用现有后端；如 Python 服务已存在，可使用 NumPy、SymPy（符号验证/计算）、SciPy（复杂约束求解，后期）。
- 动态滑动参数在**浏览器本地**计算，不要每一帧请求 LLM 或远程后端。

**方案 B（快速 Python 实验原型）：**
- `Viser` 提供 Python 端 3D 基元、GUI 滑块、场景点击与 transform gizmo，很适合验证交互方案。
- 但对于**高度定制的学生界面、题面/场景/构造/测量的完整工作台**，生产形态一般更推荐直接控制 Web 前端，而不是强行将 Viser 作为全部 UI 基础。

**已有成熟产品可参考的交互：** GeoGebra 3D 提供点、线、面、空间旋转和几何构造；可以借鉴交互概念，但核心仍需自有题目解析与约束验证层。

### 8.2 实时更新路径
```text
用户更改 θ 或拖动点
 -> DragConstraintAdapter 将操作转为合法参数值
 -> ParametricEvaluator 计算新的所有点/面的坐标
 -> ConstraintValidator 校验当前状态
 -> SceneRenderer 重绘 mesh/edges/labels
 -> MetricEvaluator 重算当前所有观察量
 -> Inspector / Chart 同步刷新
```

仅 `参数 -> 几何 -> 数值` 为高频路径。AI 文本讲解在交互结束后才需要异步更新；不得参与每帧实时计算。

## 9. 数学量的测量定义与教学呈现

### 9.1 可测量对象
| 选择对象 | 可用测量 | 画面辅助元素 |
|---|---|---|
| 点 A + 点 B | 长度 AB | 亮色线段、长度标签 |
| 点 A + 直线 l | 点线距离 | 垂足 H、虚线 AH、直角符号 |
| 点 A + 平面 π | 点面距离 | 垂足 H、垂线 AH、底面半透明 |
| 直线 l1 + 直线 l2 | 线线夹角（可异面） | 平移方向向量至公共起点、角弧 |
| 直线 l + 平面 π | 线面角 | 投影线、角弧、符号定义 |
| 两个面 + 指定公共棱 | 二面角 | 垂直于公共棱的截面及相交射线 |
| 三棱锥/棱柱 | 体积 / 表面积 | 底面突出、高度线、数值 |

**要区分图形直观与数学定义：**
- 两条异面直线的夹角可以算，但不能画成它们在某处真实相交；要用平移后的辅助向量表示。
- 两平面的最小夹角与指定半平面形成的二面角不同；有公共棱时须按题面指定方向构造截面。
- 极值曲线上的“看似最高点”是数值观察结果；若要提示“最大值”，必须有额外数值验证或解析证明支持，并标清验证级别。

### 9.2 教学内容分层
- 观察层：点线面如何运动，量测值如何变化。
- 解释层：为什么连这条辅助线，为什么这个量能表示所求角/距离。
- 推导层：数学公式与严谨推导（独立于绘图数值）。
- AI 提示默认只给小提示，用户点击“下一步”再推进，避免直接暴露完整解答。

## 10. 第一版示范场景与验收案例

### Demo A：正方形沿 DE 翻折（最高优先级）
- 初始：正方形 ABCD 边长 4，E 为 AB 中点。
- D、E 是固定折痕端点，活动面 ADE 是刚体，底部 EBCD 固定。
- 学生滑动 θ：0°→90°。
- 显示：折前虚影、翻折后的运动面、折痕高亮、A′ 到底面高度、A′B 长度。
- 支持选择 A′ 与 C，新建 A′C 辅助线；线段跟随折叠实时变化。
- 数学断言：`|AD|`、`|AE|`、`|DE|` 在整个折叠过程中不变；点 D、E 固定；A 的 z 坐标按给定折叠方向改变。
- 这里 `E` 是**折前** AB 的中点，翻折后 **不是** A′B 的中点。

### Demo B：正方体/长方体空间角
- 点选一条空间对角线和一个平面，高亮投影线。
- 显示所成角数值；更改合法的长方体边长参数后，角度自动变化。
- 侧栏显示投影关系，不只是数字。

### Demo C：三棱锥中点与点面距离
- 点 E 是 AB 中点，通过构造依赖实时计算。
- 可在边 AB 上创建滑动点 P，滑块 t 控制 AP/AB=t。
- 选择 P 和平面 BCD，显示垂足和距离曲线。

### 验收用例（必须自动化或人工录屏核验）
1. 上传 demo A 文本与示意图后，AI 结构化识别所有点和正确折痕 DE。
2. 0° 折叠时活动面在初始平面内；90° 时活动面在空间内，所有刚体长度恒定。
3. 对 θ 做 0°、15°、30°、45°、60°、75°、90° 采样，残差全部不超容差。
4. 在 30° 和 75° 分别量测 A′ 到底面距离，显示值与独立计算一致。
5. 创建辅助线 A′C，滑块运动时端点始终贴合顶点。
6. 右侧隐藏/显示底面后，线与标签逻辑仍正确，鼠标命中不混乱。
7. 无法读清题目关键条件时，提示纠正而不是强行“已验证”。
8. 题图画得不按比例时，模型仍以**文字条件**为准。
9. 几何退化（如三点重合）时不出现 NaN、页面崩溃、无意义的角度。
10. 题目已有线段 AB 与学生新建线段 AB 命名冲突时能避免重复对象/提供明确提示。
11. 手机与桌面至少完成折叠滑块、点选、加线、重置的核心闭环。
12. AI 接口失败时保留题图和文字，不丢失已上传的内容。

## 11. API 与持久化建议

不强制改变现有工程接口；以下是逻辑上的接口契约。

### 后端接口
- `POST /geometry/parse`：接收已有图片资源 ID（或识别后的题面数据），返回 `ProblemIR + uncertainties`。
- `POST /geometry/plan`：接收 ProblemIR，返回可视化等级与场景规划；可合并到解析流程。
- `POST /geometry/compile`：接收 ProblemIR/Planner 输出，返回 `GeometryScene + validation_report`。
- `POST /geometry/validate`：校验场景对象引用、数学约束和运动参数采样；开发时也可作为内部函数而非公开端点。
- `GET /geometry/scenes/{problem_id}` / `PUT ...`：读取/保存已验证场景与学生构造层（如现有数据层允许）。

### 建议持久化字段
`problem_id`、`image_id`、`problem_text`、`problem_ir_version`、`scene_schema_version`、`scene_json`、`validation_report`、`model_version`、`parser_version`、`user_constructions`、`viewport_state`、`created_at`、`updated_at`。

### 缓存与版本
- 根据规范化题目文字 + 图片指纹 + 编译器版本缓存生成结果。
- 更新模型版本或编译器后，旧场景保持可回放、可重验，不静默改写学生已保存构造。
- 写入完整场景时保存 `validation_report`，前端只对验证通过且支持的部分开放交互。

- 复用现有图片 AI 模块，生成 ProblemIR；实现条件确认 UI。

## 13. 给 Codex 的直接执行指令

> **工作原则：小步实现、可运行、可测试、不要为了“看起来有 3D”牺牲数学正确性。**

## 14. 风险清单与工程判断

| 风险 | 典型失败 | 应对 |
|---|---|---|
| AI 读图错误 | 把交点错认成顶点、漏掉垂直符号 | 文字/条件确认，可追溯题图区域 |
| 约束不足 | 生成一种构型却宣称唯一 | 展示自由参数与“示意构型” |
| 几何坐标幻觉 | 数值不满足长度/垂直 | GeometryValidator；模板优先 |
| 任意拖点难以实现 | 拖动后刚性面变形、约束跳变 | 优先参数驱动 + 约束投影 |
| 数学定义歧义 | 二面角补角、异面线夹角画错 | 明确定义和可视化辅助对象 |
| 依赖刷新不一致 | 点动了，线/指标没动 | 单一场景状态与统一求值器 |
| AI 延迟和费用 | 拖动要联网调用模型 | AI 仅生成阶段；拖动本地计算 |
| 手机交互困难 | 点太小、3D 拖动无法理解 | 专门的参数控件与移动底部抽屉 |
| 学习目标偏离 | 界面像专业 CAD，学生不会用 | 教学模式默认极简、逐步解锁 |
