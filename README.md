# 知序 · v2.0

高中数理学习项目。本分支保存当前立体几何学生端前端及配套接口契约、内容和开发样例。

**当前定位：学生端前端已贯通，真实学生认证和 PostgreSQL 账号、会话已接通；知识、练习、结果与历史后台仍待接入。v2.0 不代表完整产品已上线。**

正式工程入口是 **[platform/](platform/README.md)**，采用 Next.js、TypeScript、Tailwind。根目录 `index.html`、`src/`、`data/` 属于较早的 HTML 原型，不能代表 v2.0 的功能或运行方式。v2.0 需要启动应用服务，不能仅双击 HTML 运行。

## 当前完成了什么

| 模块       | 已完成内容                                                             | 当前实现边界                                                           |
| ---------- | ---------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| 账号       | 用户名与密码注册、登录、退出、登录状态恢复及未登录跳转                 | 真实学生认证与数据库会话已实现；知识与练习服务仍待接通                 |
| 知识学习   | 六单元目录、知识详情、概念、定理条件、配图、例题、易错点及练习入口     | 内容已按公开 DTO 接入；正式题库内容发布仍需复核                        |
| 练习创建   | 全部题目、按单元/难度/题型筛选、指定题号三种模式                       | 题数动态读取，不写死五题；当前开发题库为 24 题                         |
| 题型输入   | 单选、多选、填空、判断说明、证明、证明计算、探究证明、综合解答八种题型 | 多空、多值、判断理由与各分问分别保存；前端只校验结构，不判断数学正确性 |
| 作答过程   | 题号导航、进度、漏答定位、确认提交、本机草稿、刷新恢复及存储失败提示   | 草稿仅保存在当前浏览器，退出会清除，不是跨设备或服务端草稿             |
| 提交恢复   | 防重复点击、提交状态恢复、网络不确定时锁定原答案并重试                 | 正式服务仍需落实事务、幂等与并发控制                                   |
| 结果       | 本人答案、参考答案、解析，以及正确/错误/待复核三态                     | 有待复核题时总分为 null，不计为答错或零分；没有人工复核后台            |
| 历史与重练 | 本人提交历史、分页、结果详情、当前结果错题筛选及重练、同题组重练       | 重练创建新练习、保留旧结果；尚无独立完整错题管理系统                   |
| 公共前端   | 沿用知序既有风格，统一布局、公式文本、原图、状态与错误反馈，适配手机   | 所有正式前端代码均在 platform，不引用根目录旧原型状态                  |
| 接口接入   | 统一封装契约 v2 的 11 个业务调用，处理 Cookie、响应结构和业务错误      | 默认请求 /api/v1；health 与四个认证路由已实现，其余业务仍待接通        |

六单元包括：空间位置关系、线面平行、线面垂直，以及空间角、距离与体积、空间向量。开发数据覆盖 Q01—Q24；题目目前均为 DRAFT，不能据此宣称正式题库已发布。

## 现在可以怎样体验

要求 Node.js **24.22.2**、pnpm **12.16.1**。先进入本分支的 `platform/`，按锁文件安装依赖。

### Windows PowerShell

```powershell
git clone --branch feature/platform-init --single-branch https://github.com/oj-afraid-student/-.git zhixu-v2
cd zhixu-v2/platform
pnpm install --frozen-lockfile
Copy-Item .env.example .env.local
$env:ZHIXU_DEV_FIXTURES='1'
pnpm dev
```

### Linux / macOS / WSL

```bash
git clone --branch feature/platform-init --single-branch https://github.com/oj-afraid-student/-.git zhixu-v2
cd zhixu-v2/platform
pnpm install --frozen-lockfile
cp .env.example .env.local
ZHIXU_DEV_FIXTURES=1 pnpm dev
```

浏览器打开 <http://localhost:3000>，自行注册符合格式要求的账号，再登录。推荐路径：知识学习 → 选择单元 → 阅读概念与例题 → 创建练习 → 完整作答 → 查看结果 → 查看历史或重练错题。

上述命令显式开启开发样例服务 `/api/development`：账号、练习与记录保存在进程内存，页面刷新或退出重登后可回看，**服务重启后清空**。它用于前端开发及回归，不是正式账号或数据库服务；页面有开发环境说明，生产运行始终禁用该服务。

关闭开发开关时，前端访问正式 `/api/v1`，不会在接口失败后自动回退成功样例。真实账号可使用；练习完整流程尚待其余业务接通。真实认证运行与验证见 [认证交接](platform/docs/auth-handoff.md)。

## 当前没有传题功能

**v2.0 正式工程没有题目上传入口。** 当前练习来自已有的 24 题；指定题号只是选题，不是上传新题。

早期 V1.0 的“预置图片伪上传 → 预设解析 → 保存资料”属于历史原型流程，本次没有迁入正式工程。真实文件上传、OCR、题目解析、条件确认与资料入库接口均尚未实现。

## 距离完整项目目标还差哪些实现

| 方向               | 仍需完成的工作                                                                                                                                  |
| ------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| 正式账号与权限     | 真实注册、登录、退出、me、数据库会话及统一身份读取已完成；练习和结果服务仍须基于真实身份落实资源归属校验                                        |
| 数据库与业务服务   | 按 [v2 迁移](platform/docs/contracts/storage-handoff.md)接通多题型答卷和其余正式业务接口，验证事务、并发提交及跨账号隔离 |
| 题库与教学内容     | 复核六单元、24 题、配图与解析，建立正式发布和版本管理；题库不能停留在 DRAFT 或开发 fixtures                                                     |
| 判题与复核         | 接入正式客观题判定；保存含推理题的过程，定义复核角色、权限和录入接口；复核完成后才形成最终分数，不能把证明题预设为自动批改完成                  |
| 上传与个人资料库   | 支持题目文字及题图上传、文件校验、保存与读取；接入 OCR/解析，核对缺失或冲突条件，经用户确认保存本人资料；正式题库发布另行审核                   |
| 题目重构与交互模型 | 将支持范围内的数理情境转换为可交互模型或仿真，逐步接入立体几何、物理板块等已有设计；处理参数约束、辅助关系、识别失败及不支持场景                |
| 个性化学习         | 基于真实作答建立知识关联、掌握度分析、学习画像、推荐与个性化测验；不能把写死的指标当成算法效果，需区分独立首答、提示与重练                      |
| 教学与扩展功能     | 按团队最终确认范围推进教师、班级、练习发布和教学反馈；这些旧原型设想尚未进入当前正式学生端                                                      |
| 部署与交付         | 接通真实 PostgreSQL 与正式运行环境，完成配置、持久化、备份及必要监测；关闭开发模式，用真实账号和数据完成跨设备、重启保留、权限与完整流程验收    |

优先完成真实账号 → 知识读取 → 创建/提交练习 → 判题与保存 → 历史回看，再逐步接入上传解析、资料库、模型重构和个性化能力。以上是实现缺口与接入顺序，不是新增功能已经完成的承诺。

## 验证情况与边界

本分支的业务代码继承已验证的 `eb45ac2`，本次 v2.0 归档仅更新 README，未改变业务逻辑、接口契约、依赖或数据库。

- `pnpm check` 已通过：格式、ESLint、路由与 TypeScript、25 项测试、生产构建。
- 38 份实际 JSON 契约样例通过严格类型检查。
- 开发 HTTP 闭环与 16 组桌面/手机浏览器验收通过，包含实际填写 24 题、立即刷新、提交断网、分页和双账号隔离。
- 生产环境误开开发开关时，开发接口仍关闭；客户端产物不包含服务端私有判题字段。
- 上述开发和 PGlite 测试不代替真实认证、PostgreSQL、正式判题/授权与人工复核的验收。

详细证据见 [前端验证记录](platform/docs/frontend-verification.md)；接口定义见 [API 契约 v2](platform/docs/api.md)；团队接入说明见 [前端交接](platform/docs/frontend-handoff.md)。
