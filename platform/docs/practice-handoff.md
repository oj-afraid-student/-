**穆泓烨的开发工作已完成（按团队最新同步）；王宁岳的练习后端已实现并通过本地验证。接下来由赵景言完成正式内容与知识服务，由李梓禾完成真实前端联调和使用材料。**

## 已经可以使用的能力

真实认证、数据库及事务基础已提供。王宁岳已实现以下接口，前缀均为 `/api/v1`，请求和响应沿用[API v2](api.md)，无需重写现有页面：

| 接口                         | 用途                                                      |
| ---------------------------- | --------------------------------------------------------- |
| `POST /practices`            | 全部题、筛选、指定题号创建练习                            |
| `GET /practices/:id`         | 读取本人练习及提交状态                                    |
| `POST /practices/:id/submit` | 校验、判题、事务保存；相同答案返回原结果，不同答案返回409 |
| `GET /me/submissions`        | 本人提交历史，支持分页                                    |
| `GET /me/submissions/:id`    | 本人答案、参考解析及三态结果                              |

已通过37项测试；此前完整工程检查、生产构建及真实PostgreSQL HTTP验证通过，覆盖并发、回滚、权限、版本固定和应用重启后回看。正式内容与页面仍需完成下面的联调验收。

## 赵景言需要完成什么

1. **复核并导入六单元、24题。** 检查题干、选项、答案、填空别名、解析、知识关联、配图和来源，留下审核记录。接通初始化入口，只发布审核通过的题；现有DRAFT样例不能直接当作正式发布内容。
2. **接通题库读取。** 对照 `src/server/practice/contracts.ts` 和现有 `practice/catalog.ts` 适配器，与王宁岳核对两个方法：`listPublished()` 取每题最新已发布版本；`loadQuestionVersions(versionIds)` 按内部UUID读取固定版本，包括已下架版本。内容修改新增版本，保留旧解析和图片。
3. **实现两个知识接口。** `GET /knowledge-points`、`GET /knowledge-points/:id`，字段按现有契约。
4. **接通学习和历史页面。** 学习目录、详情使用真实知识接口；历史使用上面的两个查询接口。检查分页、空记录、请求失败及结果跳转，不能把请求失败显示成空历史。
5. **完成内容走查。** 与李梓禾交叉检查图文、作答结构和解析可读性，记录代表性用户反馈。

**交付标准：** 关闭开发样例后能浏览六单元、选取审核发布的题；Q05/Q14/Q24经正式导入、提交后可按原版本读回；历史可分页并打开本人结果；题目换版不改变旧答卷。

## 李梓禾需要完成什么

1. **关闭开发样例，接真实流程。** 设置 `ZHIXU_DEV_FIXTURES=0`，使用穆同学提供的运行环境，联调注册、登录、退出、会话恢复和失效，以及创建、作答、提交、结果页面。
2. **检查三种组题和八题型输入。** 重点检查Q03多选、Q05判断与理由、Q06三空、Q14两个无序值、Q24三问，以及切题、漏答定位和草稿恢复。沿用现有DTO，不在前端判题。
3. **验证提交与异常恢复。** 检查确认提交、重复点击、断网及刷新。结果不明时读取练习：OPEN用原答案重试，SUBMITTED打开返回的submissionId；退出清理当前账号草稿，请求失败不显示成功。
4. **核对结果和重练。** 显示本人答案、参考解析和正确/错误/待复核三态；有待复核题时总分为空，待复核不计入错题。错题或整组重练用EXPLICIT创建新练习，保留旧结果。当前规则取最新已发布版本；某题全部下架时返回404，页面需明确提示。
5. **完成桌面、手机验收和材料。** 检查公式、几何图、表单及错误提示；整理使用说明、演示步骤、截图，并更新页面完成情况。

**交付标准：** 真实账号能完成创建→作答→提交→结果→重练；刷新和断网恢复正确，待复核不显示成零分或答错，手机操作可用。

## 两人共同跑通的最后一轮
