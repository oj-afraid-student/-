# 学生端使用说明与操作步骤

维护：李梓禾；2026-11-08。正式工程为 `platform/`，需要启动 Next.js 服务，不能双击 HTML 使用。

## 启动与环境

使用 Node.js **24.22.2**、pnpm **12.16.1**，进入 `platform/` 执行 `pnpm install --frozen-lockfile`。

本地页面开发可以不连数据库：

```powershell
$env:ZHIXU_DEV_FIXTURES='1'
pnpm dev
```

打开 <http://localhost:3000>。自行注册账号，不提供固定账号或自动填入的答案。顶部会标明开发样例环境，账号、练习和答卷只在进程内存保存，服务重启会清空。

真实认证与练习联调：按 [数据库说明](../db/README.md) 配置未提交的 `.env.local`、执行 `pnpm db:check` 和 `pnpm db:migrate`，设 `ZHIXU_DEV_FIXTURES=0` 后运行 `pnpm dev`。部署使用 `pnpm build` / `pnpm start`，共享访问须配置 HTTPS。开发接口在生产环境始终关闭，即使误设开关也不会启用。

当前上游还没有知识目录/详情正式接口、正式内容导入与审核发布流程。`db:seed` 只补三个单元元数据，不会发布 24 道题。目录失败时选题页仍能使用全部题、题型/难度筛选和指定题号；正式练习需要库中存在已发布内容。不要把测试脚本临时写入的题目当作正式内容审核完成。

## 一次学习与练习

1. 在 `/register` 创建学生账号：用户名为 4—20 位字母、数字或下划线，密码 8—64 位；用户名会去除首尾空格并转小写，密码保留空格。注册成功后仍需登录。登录状态过期时返回登录，成功后回到原受保护页面。
2. 在 `/learn` 选择单元，在 `/learn/[id]` 阅读概念、定理条件、例题、公式和静态配图。点图片可在新标签查看原图。知识服务未接通时会明确报错，不会悄悄换用开发数据。
3. 在 `/practice/new` 选“全部题目”“按条件选题”或“指定题号”。条件可含单元、难度、多个题型和题量；指定题号用逗号、空白或换行分隔。题量不足按服务端提示减少数量；未发布或下架的题不可选。
4. 在 `/practice/[id]` 按题号导航。题数由服务端返回，既可一题也可 24 题。Q03 可多选；Q05 每项判断和理由都要填，选择“错误”也是有效判断；Q06 三空分别填；Q14 一个空含两个值，分别填写；Q24 三问分别保留过程。绿色题号只表示填写完整。
5. 点“检查并提交”，漏答会定位到对应题项与字段。确认全部答案后提交。答案按 `practiceItemId` 发送；前端只校验结构，不在浏览器判断数学正误。填空值首尾空白按现有契约移除，内部空白、全角字符和推理原文保留。
6. 在 `/results/[submissionId]` 回看固定版本的题干、原选项/分问、配图、本人答案、参考答案和解析。只有正确/错误已确定的题计入已判；待复核不算错题，有待复核时最终总分为空。
7. 点“错误”只筛本次明确判错的题。“重练本次错题”或“再练同一题组”会新建练习，使用各题当前最新已发布版本，原答卷不覆盖。若任一题已完全下架，本次重练整体失败并保留原结果，不生成残缺题组。
8. 在 `/history` 查看本人正式提交，按页切换并打开同一结果。未提交练习不算历史记录。公共设备完成后退出；退出成功后清除当前账号的本机草稿。

## 草稿与异常恢复

| 情况                          | 页面行为与处理                                                                           |
| ----------------------------- | ---------------------------------------------------------------------------------------- |
| 输入后立即刷新                | 同一浏览器、账号、练习和题目版本匹配时恢复草稿；本机草稿不等于服务端保存                 |
| 网络失败、503、提交结果不确定 | 锁定原答案，先查询原练习；已提交则进入同一结果，仍为 OPEN 则用原答案重试，不能修改后覆盖 |
| 失败后刷新或登录过期          | 保留原提交快照；重新登录原账号、回到原练习，点“重新查询提交状态”或“使用原答案重试提交”   |
| 后台确认会话时暂时断网        | 非阻塞提示，输入保留；恢复后点“重新确认登录状态”                                         |
| 400 结构校验错误              | 解锁，按错误提示修改后重新确认提交                                                       |
| 另一标签改为其他账号          | 回到页面时重新确认当前用户，清除页面中前一账号的数据视图；归属仍由服务端校验             |
| 草稿版本不匹配、数据损坏      | 明确提示，不把旧内容自动套到新版本；损坏的锁定快照不拼装为不同的重试请求                 |
| 浏览器存储禁用或写满          | 提示无法保存草稿；保持当前页面打开，避免刷新，尽快完成提交                               |

主动退出会清理本机草稿；清除浏览器数据、换设备也无法恢复未提交内容。已经服务端保存的答卷可以从历史回看。当前没有上传、OCR、人工批改后台、AI、交互模型或画像功能。

## 建议的短操作顺序

先使用开发样例验知识目录和图文，再关闭开关验真实账号与练习。正式内容尚未发布时，可在隔离测试库运行下述自动验收；不要直接向共享库发布 fixture。

1. 注册、登录 → 六单元与一张原图（知识部分当前仅开发样例通过）。
2. 指定 `Q05,Q06,Q14,Q24` → 填判断理由、多空、多值、三问 → 刷新确认草稿。
3. 全部 24 题 → 故意漏答 → 补全并提交 → 核对三态、11 已判/13 待复核和空总分。
4. 五道选择题做 3 对 2 错 → 只筛错误 → 重练错题 → 回到原结果。
5. 模拟断网提交 → 刷新锁定快照 → 恢复连接 → 查询/原答案重试 → 历史回看。
6. 退出后用另一账号访问原结果，确认不可访问。手机复查三问输入与提交。

完整验证边界、命令和截图见 [本轮验收记录](frontend-integration-verification.md)。
