## 1. 共同起点

- 仓库 `oj-afraid-student/-`，团队分支 `feature/platform-init`。本稿核对的远端提交是 `a2a1283`。穆泓烨在这个基线上完成并验证了 `002_practice_v2.sql`。开始接真实数据库读写前，核对自己的工作分支是否包含穆泓烨同步的迁移版本。
- 正式工程在 `platform/`，沿用 Node.js 24.22.2、pnpm 12.16.1。进入该目录执行 `pnpm install --frozen-lockfile`。本地前端可用 `ZHIXU_DEV_FIXTURES=1 pnpm dev` 独立开发。真实联调用 `ZHIXU_DEV_FIXTURES=0` 并配置本机 PostgreSQL，按 `db/README.md` 初始化。开发样例只存在内存，生产构建关闭开发接口。
- v2 接口以 `platform/docs/api.md`、`platform/src/shared/contracts/learning.ts` 和 `platform/fixtures/api/` 为准。逐题参考 `platform/docs/contracts/question-matrix.md`。按此继续现有实现。发现字段、状态或含义需变动时，由王宁岳给出受影响调用方和一对新旧样例，合入前同步文档、类型、页面和测试。
- 远端已有真实账号四接口、认证守卫、事务入口和通过的 Actions。已有页面覆盖六单元、三种组题、八题型输入、草稿、结果和历史，完整流程此前使用开发样例。现有 24 道题全部是 `DRAFT`。六单元正式发布、真实知识与练习服务、答卷持久化和团队共享环境待各线接通。
- `002` 的字段与读写说明见 `platform/docs/contracts/storage-handoff.md`，24 题的实际数据库写入与读取样例见 `platform/tests/database-v2.test.mjs`。本机 PostgreSQL 17 已验证旧五题升级、空库初始化、备份恢复与真实认证。

## 3. 对接时直接使用的约定

- v2 组题为 `ALL`、`FILTERED`、`EXPLICIT`。筛选使用 `knowledgePointId`、`difficulty`、`questionTypes`、`count` 的现有定义。显式组题按传入题号顺序。候选范围使用已发布题。正式接口仍是既有 11 个业务入口。
- 提交为 `{ answers: [{ practiceItemId, answer }] }`。首提 201，相同答案重试 200 并返回同一 `submissionId`，换答案重提 409。历史使用 `page`、`pageSize`。练习读取与创建只返回公开题目，结果详情才返回参考答案和解析。错误使用现有 v2 的 `code` 和 `message`。
- 使用 Q03 多选、Q05 判断和理由、Q06 三空、Q14 一空两个无序值、Q24 三个分问联调。正式作答按契约校验并保存学生文本与结构化值，判题及重试比较使用约定的规则，避免用比较后的值覆盖已接收的作答。单题三态为 `CORRECT`、`INCORRECT`、`PENDING_REVIEW`。有待复核题时总分为空，待复核不进入错题。
- 沿用当前同浏览器草稿口径。按账号、练习及题目版本隔离，刷新可恢复，主动退出清理当前账号草稿。提交不确定时先查原练习，仍为 `OPEN` 时用同一份答案快照重试，已为 `SUBMITTED` 时打开返回的提交。重新登录可从历史打开已正式保存的答卷。
- `@/server/auth` 的 `requireCurrentUser()` 返回 `{ id, username }`。`@/server/db` 的 `withTransaction()` 提供同一事务连接。正式接口必须在服务端检查练习、题项和提交归属。无会话 401，访问他人的个人资源与不存在均返回 404。

## 4. 直接发给各自 AI 的任务

所有人把下面的通用指令和自己的任务一起交给 AI。

> 阅读仓库指令、当前分支、本说明和现有 v2 接口类型。先报告本模块已有实现和待接入边界，基于现有页面、类型和样例完成自己的任务。凡是依赖他人还未合入的服务，先用现有样例或清晰的测试替身验证本模块，继续推进独立部分。完成时列出修改路径、验证命令、实际通过的场景、对其他人的输入输出，以及剩余阻塞。真实接口和开发样例分别验收。

## 6. 一次正式验收

1. 关掉开发样例，注册和登录两个真实学生账号。逐个打开六个单元，检查公式、静态配图、例题和题目关联。用 `ALL` 取得复核后发布的 24 题，再验筛选与指定题号的数量、顺序和空结果。
2. 用五道确定可判的题做 3 对 2 错回归。再做跨单元混合练习，覆盖八题型，保留多空、多值、布尔判断和理由、分问原文及三态结果。故意漏答或提交另一练习的题项，核对提示和未落库。
3. 模拟保存中断、重复点击和并发请求。确认失败回滚，同一答案只产生一个提交，冲突不能覆盖原结果。断网后恢复并打开同一 `submissionId`。
4. 刷新未提交练习，验证同浏览器草稿。刷新、退出重登、重启应用和数据库后，从历史打开相同正式记录。用第二账号尝试读、提交、回看第一账号的记录，验证 404 和个人列表隔离。
5. 发布新版题目与配图，旧答卷的题干、选项、图、原文、解析和判定保持可读。用旧库快照验证迁移，再用备份恢复的测试库验证记录。
6. 主线通过后，在结果中只筛 `INCORRECT`，分别重练错题和整组。验证新练习 ID、旧记录和下架提示。记录页面、接口、落库和启动证据。
