# 协作与代码合入

## 独立工程边界

全组从仓库的同一提交创建任务分支，只在 `platform/` 开发正式系统。应用代码不得引用 `../../src`、根目录 data、原有 HTML 或其状态逻辑。新增 GitHub 检查仅处理正式工程。

Next.js 的配置、类型检查、CSS 扫描与依赖安装以 `platform/` 为根；不要把外层现有 `src/` 加入 tsconfig、构建配置或资源扫描范围。所有运行命令先进入 `platform/`。

## 公共约定

- 全组使用同一 Node.js / pnpm 版本；只维护 `pnpm-lock.yaml`。
- 工程依赖、数据库迁移由赵景言协调。需要加包时在 PR 中说明，避免并行升级基础库。
- 共享类型由王宁岳维护。字段改名、删除、含义改变先更新契约，并通知调用方。
- 客户端和业务页面通过公开接口访问数据；数据库连接和答案库只在 server 目录使用，敏感模块加 `import 'server-only'`。
- 完整题库与正确答案样例放 `fixtures/server/`，不要放进 public 或公开题目响应。
- API 入口使用 `src/server/http.ts` 的成功和失败封装；不要把原始异常传给浏览器。
- 个人练习与结果由服务端根据当前用户校验；不能信任请求中的 userId 或浏览器角色切换。
- UI 使用本地系统字体。公式与图形组件由穆泓烨统一封装，配图由李梓禾维护。

## 每次合入

1. 从主分支最新提交建立小任务分支。
2. 只改本任务相关文件。接口、公共配置、数据库变更找维护人共同复核。
3. 同步最新主分支，解决自己分支中的冲突。
4. 在 `platform/` 运行 `pnpm check`；数据库结构有变更时增加迁移和有区分度的约束测试。
5. 提交 PR，写清改了什么、怎么验证、是否改变接口或数据结构。
6. 检查通过并由另一名成员复核后合入。

穆泓烨与李梓禾交叉检查界面和内容，赵景言与王宁岳交叉检查服务端及保存行为。保持主分支可启动，模块逐步合入，不集中到第三周末才集成。

首日交接后，业务分支均以本工程为基线继续开发。GitHub CI 检查格式、代码、类型、数据库约束及构建；它不代表真实注册登录或五题提交已经验收。

## 本轮前端接入边界

本轮前端只修改页面、公共组件、请求、开发适配及验收资料，不修改共享契约、题库答案、数据库迁移、依赖版本和导入规则。/api/development 是显式开启且仅 development 可用的隔离服务，不接管 /api/v1。检查通过后仍由其他成员复核合入，不自动合并。中期准备已结束，后续面向完整项目推进，历史三周样例节点不再作为完整产品验收标准。
