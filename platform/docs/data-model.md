# 数据模型与内容交接

当前正式接口使用 PostgreSQL 与 `pg` 参数化查询，必须顺序应用 `001_initial.sql`、`002_practice_v2.sql`。迁移由穆泓烨维护，本轮练习服务未修改迁移。详细字段见 [v2存储交接](contracts/storage-handoff.md)。

| 表                     | 当前用途                                                                                        |
| ---------------------- | ----------------------------------------------------------------------------------------------- |
| app_user / app_session | 真实学生账号、密码哈希、可失效的数据库会话                                                      |
| knowledge_point        | 单元与知识内容，由赵景言导入和提供知识接口                                                      |
| question_version       | 公开题目、参考解析、判定规则和来源分别存储；题号+版本唯一，内容不可变，is_published控制当前选题 |
| practice               | 归属当前用户，保存三种创建模式的selection快照，状态OPEN/SUBMITTED                               |
| practice_item          | 1—100个固定题项，保存题序和内部题目版本UUID                                                     |
| submission             | 每练习唯一结果；数据库生成待复核数量、判定状态及可空总分                                        |
| submission_answer      | 八题型结构化答案与可空is_correct；数据库生成三态结果和单题分数                                  |

王宁岳的服务校验全部题项、题型、选项、空位、分问和个人归属；同一事务锁定练习，保存结果与答案并更新状态。相同答案返回原提交，不同答案409，失败回滚。查询固定原版本，不因新版或下架改变旧答卷。历史按时间和ID双降序分页。见[练习服务交接](practice-handoff.md)。

## 内容与版本

现有六单元、24题、八题型仍为DRAFT开发内容。正式导入与审核由赵景言负责，不能把能保存题目当作题目已审核。导入公开部分必须符合 `PublicQuestion`，答案与判题规则不能进入公开字段；跨单元和细分知识点分别由unitIds、knowledgeIds关联。

新题写002的public_question、reference_answer、grading、source字段，不使用旧单选列。内容变化新增版本；每题最新已发布版本进入新练习，未发布新版不遮蔽旧版。内部版本读取允许已下架题，以保证历史可回看。

原图保持ABCD—A₁B₁C₁D₁命名；图形组件由李梓禾维护，配图与来源由赵景言复核。图片内容变化使用新地址并保留旧文件。主观过程仅保存与参考解析对照，不自动批改。

001中的固定五题单选约束仅属于历史结构；002保留旧数据并扩展多题型。旧五题记录保持原计数，新接口按实际题量工作。种子命令目前只导入三个单元元数据，不等于六单元和24题的正式导入。
