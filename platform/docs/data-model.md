# 数据模型与内容交接

数据库使用 PostgreSQL，通过 `pg` 参数化查询。迁移由穆泓烨维护；当前结构是首日基线，业务负责人增字段时先对齐契约，再新增迁移。

| 表                | 用途与关系                                                         |
| ----------------- | ------------------------------------------------------------------ |
| app_user          | 学生账号，规范化用户名唯一，保存密码哈希                           |
| app_session       | 用户会话，保存随机令牌的哈希与过期时间；由 AUTH-01 接入            |
| knowledge_point   | 单元、简介、内容、例题、图形、显示顺序                             |
| question_version  | 稳定题号与版本、单元、题干、四选项、正确选项、解析、图形、发布状态 |
| practice          | 属于学生和单元的一次练习，状态 OPEN / SUBMITTED                    |
| practice_item     | 练习内固定题序，引用不可变的题目版本                               |
| submission        | 一次最终提交，practice_id 唯一，记录正确题数和提交时间             |
| submission_answer | 每题所选选项与正误；复合外键防止引用另一练习的题项                 |

数据库约束负责用户名唯一、题目版本与选项有效性、固定题序范围、提交去重和关联完整性。服务端仍须校验个人归属、五题齐全、选项有效、练习与题目单元一致，并在事务内保存完整结果。首日结构不代表这些业务接口已实现。

## 李梓禾的内容输入

三个单元：SG-01 空间位置关系、SG-02 直线与平面平行、SG-03 直线与平面垂直。每单元计划五道人工核验单选题。

- `knowledge_point.content` 使用 JSON 对象，建议含学习目标、概念、定理条件和易错提醒；`examples` 为例题数组。具体字段由李梓禾和王宁岳共同确定。
- 图形对象遵循共享 `Figure`：`id`、`src`、`alt`、`caption`。资源路径从 `/geometry/` 开始，使用版本化文件名。
- `question_version.options` 为四项数组，每项 `{ id, text }`，编号唯一；`correct_option_id` 必须属于选项。
- `question_version.explanation` 为含非空 `steps` 数组的对象；可补充预先编写的易错提醒，不根据一次作答推断真实错误原因。
- `source_note` 记录来源或原创说明；内容与答案交叉核验后再将版本标为已发布。
- 题目版本内容不可原地覆盖，修订新增版本；历史练习固定引用旧版本。

知识和正式题目由业务负责人填入，首日种子只提供三个单元的元数据，不生成账号或成绩。

## 几何图形

正方体顶点统一 ABCD-EFGH，上下对应固定；虚实线与视角一致，直角标记有文字条件依据。图形不代替题干条件，解析不能仅写“由图可知”。同题在学习、练习和结果中命名一致。

共享图形组件由赵景言维护，配图由李梓禾维护。原题配图可以公开；答案与解析样例保留在服务端目录。

## 认证方向与交接

认证采用用户名密码、服务端校验和可失效会话。会话令牌以高熵随机值签发，数据库保存 SHA-256 哈希，浏览器通过 HttpOnly Cookie 携带；生产环境启用 Secure 和合适的 SameSite。真实凭据校验、成熟库选择与会话签发在 AUTH-01 中由穆泓烨集中实现，其余模块只依赖统一守卫，首日不使用前端角色切换或固定用户代替认证。
